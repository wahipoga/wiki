    1 O que é essa wiki

    A Wiki Laços Profanos é um site estático hospedado no Cloudflare Pages, mas todo o conteúdo mora num repositório GitHub:

    github.com/wahipoga/wiki

    Ou seja: editar a wiki = editar arquivos no GitHub. Quando você salva (faz um "commit"), o Cloudflare percebe e republica o site automaticamente em 1 a 2 minutos. Nada de painel de administração, nada de formulário — é só arquivo de texto.

    Não sabe o que é GitHub? Pensa nele como um "Google Drive para código". Você navega por pastas, abre arquivos, edita e salva — tudo pelo navegador, sem instalar nada.

    2 Como o repositório está organizado

    Cada categoria tem sua própria pasta. Dentro dela, cada artigo tem sua própria subpasta. A estrutura geral é assim: 

    wiki/
├── categorias.json              ← lista as categorias (usado pela home)
├── navbar.json                  ← menu de navegação
├── lang.json                    ← idiomas disponíveis
├── index.html                   ← página inicial
├── contribua.html               ← esta página
├── 404.html                     ← página de erro
│
├── personagem/
│   ├── index.html               ← lista de personagens
│   ├── personagens.json         ← quais personagens existem
│   └── wahi/                    ← uma pasta por personagem
│       ├── index.html           ← página do Wahi
│       ├── wahi.json            ← dados do Wahi
│       ├── conteudo.md          ← texto do Wahi
│       └── galeria.json         ← imagens do Wahi
│
├── bestiario/
├── simbolos/
├── organizacoes/
│
├── assets/                      ← css e javascript (não mexa sem motivo)
└── _template/                   ← modelos para copiar

    O que é "slug"

    Slug é o nome curto do artigo, usado como nome da pasta e do arquivo. Ele é formado assim:

    • Tudo em minúsculas
    • Sem acento (á → a, ç → c)
    • Sem espaço — troca por hífen (-)
    • Só letras, números e hífen

    Exemplos:

    Wahi                → wahi
Eduarda Victoria    → eduarda-victoria
Essência Nula       → essencia-nula
O Fardo da Profecia → o-fardo-da-profecia

    O slug é o que aparece na URL. Se o slug é luke, a página fica em /personagem/luke/.

    O que você precisa editar

    Pra cada artigo, você vai mexer em 3 arquivos. Usando o wahi como exemplo (o slug dele é wahi, então os arquivos ficam em personagem/wahi/):

    • wahi.json — os dados do artigo (nome, imagem principal, campos da infobox, relacionamentos). O nome do arquivo é sempre <slug>.json, ou seja, o slug + .json.
    • conteudo.md — o texto do artigo (Características, Biografia, Curiosidades). O nome é sempre esse, não muda.
    • galeria.json — a lista de URLs das imagens da galeria. Também sempre com esse nome.

    Além disso, você adiciona o slug na lista do arquivo personagem/personagens.json, que diz quais personagens existem: 

    {
  "itens": ["wahi", "luke", "yaziell"]
}

    É essa lista que faz um artigo aparecer no índice. Se você criar a pasta luke/ com os arquivos dentro mas não adicionar "luke" aqui, o Luke não aparece no site.

    3 Criando uma conta no GitHub

    Se você ainda não tem conta, vai em github.com/signup e cria. É grátis, leva 1 minuto, só precisa de email.

    Depois de criar, configura um nome de usuário simples (sem espaços, só letras e números). É esse nome que vai aparecer como autor das suas contribuições.

    4 Fazendo um "fork"

    "Fork" é uma cópia do repositório pra sua conta. Você mexe na sua cópia sem risco de quebrar o original, e depois pede pra juntar.

    1. Acessa github.com/wahipoga/wiki
    2. No canto superior direito, clica em Fork
    3. Confirma. Agora você tem github.com/SEU-USER/wiki
    Alternativa: se você já tem acesso de escrita ao repositório original (é colaborador oficial), pode editar direto sem fork. Nesse caso pula essa etapa.

    5 Usando os templates

    A pasta /_template/ existe só pra te dar um modelo pronto. Você copia o conteúdo dela e cola onde precisa, ela mesma não é a página final.

    Exemplo: criar um personagem novo chamado luke

    1. Vai na pasta /personagem/ do seu fork
    2. Clica em Add file → Create new file
    3. No nome do arquivo, escreve luke/index.html (o GitHub cria a pasta sozinho)
    4. Copia o conteúdo de /personagem/wahi/index.html (que é o exemplo funcional)
    5. Cola e troca window.ARTIGO_SLUG = 'wahi'; por window.ARTIGO_SLUG = 'luke';
    6. Commita (ver próxima seção)

    Repete pra:

    • luke/luke.json — copia de wahi/wahi.json
    • luke/conteudo.md — copia de wahi/conteudo.md
    • luke/galeria.json — copia de wahi/galeria.json

    Depois edita personagem/personagens.json e adiciona "luke" na lista: 

    {
  "itens": ["wahi", "luke"]
}

    6 Enviando suas mudanças (commit + push)

    Commit é salvar uma mudança no repositório. Push é enviar essa mudança pro GitHub.

    Jeito mais fácil: pelo navegador

    1. Você editou um arquivo (pelo próprio GitHub, clicando no lápis)
    2. Rolou até o fim da página
    3. Escreveu uma mensagem descritiva no campo "Commit changes"
    4. Clicou em Commit changes

    Pronto. Isso já é commit + push ao mesmo tempo (o GitHub faz os dois). Você vai ver o arquivo atualizado no repositório.

    Mensagens de commit boas: descrevem o que você fez, não como. Exemplos:
    • ✅ Adiciona personagem Luke
    • ✅ Corrige data de nascimento do Wahi
    • ❌ update
    • ❌ mudei coisas

    Jeito pra quem quer usar Git no computador

    # Clona seu fork
git clone https://github.com/SEU-USER/wiki.git
cd wiki

# Faz uma mudança (cria/edita arquivos)

# Adiciona o que mudou
git add personagem/luke/

# Commita com uma mensagem
git commit -m "Adiciona personagem Luke"

# Envia pro GitHub
git push origin main

    7 Abrindo um Pull Request

    Se você fez fork, suas mudanças estão na sua cópia. Pra juntar na wiki oficial, precisa de um Pull Request (PR): um pedido formal de "por favor, junta isso".

    1. Vai no seu fork: github.com/SEU-USER/wiki
    2. O GitHub mostra um banner "Compare & pull request" no topo. Clica.
    3. Escreve um título curto (ex: Adiciona personagem Luke)
    4. Escreve uma descrição: o que você adicionou, por que, e qualquer referência que ajude
    5. Clica em Create pull request

    O PR fica aberto no repositório oficial. Quem mantém a wiki vai revisar, comentar se precisar de ajuste, e eventualmente juntar (fazer merge).

    Não fez fork? Se você tem acesso direto, as mudanças já vão direto pra wiki. Não precisa de PR.

    8 O que acontece depois

    • Seu PR é revisado — pode levar alguns dias
    • Se tiver ajuste, quem revisa comenta direto no PR
    • Você corrige, faz novo commit no seu fork, e o PR atualiza sozinho
    • Quando aprovado, o PR é mesclado (merged)
    • O Cloudflare percebe a mudança e republica o site em 1-2 min
    • Sua contribuição aparece na página de commits do repositório

    Pra ver quem contribuiu, o GitHub tem a aba Insights → Contributors em qualquer repositório.

    9 Regras de contribuição

    Conteúdo permitido

    • Informações sobre personagens, bestiário, símbolos, organizações e universo de Laços Profanos.
    • Capítulos e eventos oficiais da obra.
    • Curiosidades confirmadas (comentário da autora, entrevista, post oficial).
    • Correções de erros, ortografia, links quebrados e dados desatualizados.
    • Teorias, headcanons e fanon — desde que claramente marcados como teoria (ver seção abaixo).

    Conteúdo proibido

    • Conteúdo sexual de qualquer tipo. A wiki é um espaço público e segue a classificação da obra.
    • Conteúdo off-topic. Se não é sobre Laços Profanos, não pertence aqui.
    • Spoilers de conteúdo recente. Qualquer coisa (capítulo, personagem, revelação) só pode virar artigo após 1 mês do lançamento.
    • Teoria ou fanon apresentado como fato oficial. Teorias são bem-vindas, mas precisam estar claramente marcadas como teoria. Nunca escreva uma teoria como se fosse canon confirmado.
    • Opinião pessoal. O artigo descreve, não julga ("X é o melhor personagem" não é conteúdo de wiki).
    • Palavrões, xingamentos ou ataques. Nem em artigo, nem em discussão de PR. Respeito sempre.
    • Conteúdo gerado por IA sem revisão. Você pode usar IA pra ajudar a escrever, mas o texto final tem que ser revisado por você. Não jogue output cru.
    • Vandalismo. Apagar artigo inteiro, trocar informação por piada, inserir bobagem — tudo isso é ban imediato.

    Teoria e fanon (permitidos, com marcação)

    Teorias, headcanons e fanon são bem-vindos na wiki, desde que fique claro que não são oficiais.

    Pra marcar uma seção como teoria, use citação no Markdown:

    > 💭 **Teoria (não oficial):** aqui vai a sua teoria,
> com argumentos e referências de onde ela veio.

Depois você continua o texto normal (fato confirmado, contexto, etc).

    Ficaria assim no site:

    💭 Teoria (não oficial): baseado na cena do capítulo 3, é possível que Wahi tenha origem em uma linhagem antiga de metamorfos. A obra ainda não confirmou isso.
    • Teorias com argumentos e referências.
    • Headcanon de personagem, claramente marcado.
    • Interpretação de cena ambígua, com aviso.
    • Teoria escrita como se fosse fato confirmado — sem aviso de "não oficial".
    • Apagar ou "corrigir" teoria de outra pessoa só porque você discorda. Se quiser discordar, adiciona sua teoria ao lado.
    • Teoria que contradiz fato estabelecido pela obra sem nenhum argumento.

    Spoilers

    Se você achar realmente necessário adicionar algo recém-lançado (menos de 1 mês), coloca um aviso gigantesco no topo: 

    ## ⚠️ ATENÇÃO: CONTÉM SPOILERS DE CONTEÚDO RECENTE

Este artigo contém informações reveladas em [capítulo/episódio X],
lançado em [data]. Leia por sua conta e risco.
    Aviso faltando = PR recusado. Sem exceção. Se não tiver aviso visível no topo, quem revisa vai pedir pra ajustar ou fechar o PR.

    Código

    • Melhorar CSS, corrigir bug, adicionar acessibilidade.
    • Corrigir links quebrados, erros de JS, problemas de layout.
    • Mexer mais do que o necessário. Não reformata arquivo inteiro, não troca nome de classe sem motivo, não "limpa" código que funciona só porque faria diferente.
    • Mudança grande sem discussão prévia. Se for refatorar, criar funcionalidade, mudar layout — abre uma Issue primeiro explicando. A gente conversa antes.
    • Quebrar compatibilidade. Não remove funcionalidade existente sem motivo.

    Imagens

    • URLs externas (Imgur, Drive público, servidor próprio).
    • Arte oficial da obra.
    • Arte de fã com permissão do autor — cite o nome dele na galeria.
    • Subir imagem pro repositório. Usa URL externa. Repo é só pra texto e código.
    • Usar arte de fã sem permissão. Se pegou do Twitter/Instagram sem autorização, não coloca.
    • Imagem com marca d'água de outro site ou roubada de outra wiki.

    Formato

    • Português correto, sem abreviações de internet.
    • Um artigo por PR — fica mais fácil de revisar.
    • Dúvida? Olha o Wahi, que é o exemplo mais completo.
    • "vc", "q", "kkk", "vlw" e afins nos artigos.
    • Copiar e colar de outras wikis sem adaptar.
    • Tradução automática sem revisão.

    Fonte da informação

    Sempre que possível, cite de onde veio a informação: capítulo, episódio, comentário da autora, post oficial. Isso ajuda quem revisa a confirmar e evita "invenção" ou teoria apresentada como fato.

    Conduta

    • Respeito com outros contribuidores.
    • Crítica construtiva em PR — sugere melhoria, não ataca.
    • Se errou, corrige e segue em frente.
    • Briga em comentário de PR ou Issue.
    • Ataque pessoal por causa de gosto (personagem favorito, ship, etc).
    • Editar artigo alheio sem explicar o motivo no commit ou PR.

    10 Boas práticas

    Não são regras obrigatórias, mas seguindo elas sua contribuição tem muito mais chance de ser aceita rápido:

    • PRs pequenos são melhores. Adicionar 1 personagem é melhor que adicionar 5 de uma vez.
    • Escreve a mensagem do commit ANTES de mexer. Ajuda a manter o foco no que tá fazendo.
    • Confere o preview antes de commitar. Roda o site localmente ou olha o diff no próprio GitHub.
    • Não deixa PR aberto por meses. Se não vai continuar, fecha e abre outro quando puder.
    • Revisa ortografia. Passa um corretor antes de mandar. Erro bobo atrasa a revisão.
    • Se tem dúvida, pergunta antes. Abre uma Issue ou manda no Discord. Melhor perguntar do que fazer errado.
    • Mantém consistência. Olha como outros artigos estão formatados e segue o mesmo padrão.
    Dica: se você tá começando, começa corrigindo erros pequenos (ortografia, link quebrado, data errada). Isso te familiariza com o processo de PR antes de você criar um artigo inteiro do zero.
