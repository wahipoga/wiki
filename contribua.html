    1 O que é essa wiki

    O site é hospedado no Cloudflare Pages, mas todo o conteúdo mora num repositório GitHub: github.com/wahipoga/wiki .

    Editar a wiki = editar arquivos no GitHub. Quando você salva (faz um commit), o Cloudflare republica o site em 1-2 minutos. Sem painel de administração, sem formulário — é arquivo de texto.

    Quem revisa: a equipe de Laços Profanos. Os PRs chegam no repositório oficial e passam por revisão antes de entrar no site.

    2 Como o repositório está organizado

    Dois tipos de página

    A wiki tem dois tipos de página:

    • Artigos — páginas de conteúdo, tipo personagens, criaturas, símbolos e organizações. Cada uma tem sua pasta com dados próprios.
    • Páginas fixas — HTML solto, tipo a home, o contribua, o universo. Não seguem o padrão de artigo.

    Regra de nomes

    Tudo minúsculo, sem acento, sem espaço. Vale pra pasta, arquivo e slug de artigo. 

    personagens   ✓   Personagens   ✕
organizacoes  ✓   organizações  ✕
simbolos      ✓   símbolos      ✕
bestiario     ✓   bestiário     ✕

    O que é "slug"

    Slug é o nome curto do artigo, usado como nome da pasta e dos arquivos. Segue a mesma regra: minúsculas, sem acento, sem espaço. 

    Wahi                → wahi
Eduarda Victoria    → eduarda-victoria
Essência Nula       → essencia-nula
O Fardo da Profecia → o-fardo-da-profecia

    O slug vira a URL. Se é luke, a página fica em /personagens/luke/. Se é dragoes, fica em /bestiario/dragoes/.

    Todas as categorias funcionam igual

    Personagens, bestiário, símbolos e organizações seguem exatamente a mesma estrutura. Muda só o nome da pasta e do arquivo de lista. 

    personagens/    →  personagens.json    →  personagens/wahi/
bestiario/      →  bestiario.json      →  bestiario/metamorfo/
simbolos/       →  simbolos.json       →  simbolos/ressurreicao/
organizacoes/   →  organizacoes.json   →  organizacoes/cced/

    Cada artigo, em qualquer categoria, tem sempre os mesmos 3 arquivos dentro da pasta dele:

    • <slug>.json — dados (nome, imagem, infobox, relacionamentos)
    • conteudo.md — o texto do artigo
    • galeria.json — lista de URLs das imagens

    O que tem dentro de um artigo (exemplo real do Wahi)

    Usando o wahi como exemplo, os 3 arquivos dele ficam em personagens/wahi/ e são assim:

    wahi.json — dados do artigo:

    {
  "nome": "Wahi",
  "imagem": "https://exemplo.com/wahi.jpg",
  "infobox": {
    "titulo": "Informações",
    "campos": [
      { "label": "Nome completo", "valor": "Wahipogo" },
      { "label": "Gênero", "valor": "Indefinido" },
      { "label": "Espécie", "valor": "Metamorfa" }
    ],
    "relacionamentos": [
      { "nome": "Yaziell", "slug": "yaziell", "nota": "amigo de infância" }
    ],
    "historias": {
      "titulo": "Histórias / Aparições",
      "campos": [
        { "label": "História", "valor": "Laços Profanos: O fardo da profecia" },
        { "label": "Papel", "valor": "Protagonista" }
      ]
    }
  }
}

    conteudo.md — texto em Markdown. Cada ## Título vira uma seção do artigo:

    ## Características e traços

Wahi é uma metamorfa que muda de forma à vontade.

## Biografia

Cresceu ao lado de Yaziell e, juntos, enfrentaram...

## Curiosidades

- Sua data de nascimento é 07 de abril
- É a protagonista de "O fardo da profecia"

    galeria.json — lista de URLs das imagens do carrossel no fim do artigo:

    {
  "imagens": [
    "https://exemplo.com/wahi-1.jpg",
    "https://exemplo.com/wahi-2.jpg",
    "https://exemplo.com/wahi-3.jpg"
  ]
}

    A mesma estrutura vale pra qualquer artigo, em qualquer categoria. Um metamorfo no bestiário tem metamorfo.json, conteudo.md e galeria.json — mesmos nomes, mesma estrutura.

    Como adicionar um artigo novo

    O passo é o mesmo pra qualquer categoria. Exemplo: adicionar o personagem luke:

    1. Cria a pasta personagens/luke/ (pelo GitHub, ao criar o arquivo luke/index.html)
    2. Copia o index.html, o wahi.json (renomeia pra luke.json), o conteudo.md e o galeria.json pra dentro dela
    3. Edita os 3 arquivos com os dados do Luke
    4. Adiciona "luke" em personagens/personagens.json

    É essa última etapa que faz o Luke aparecer no índice. Se você criar a pasta e os arquivos mas esquecer de adicionar o slug no personagens.json, o artigo existe no repositório mas não aparece no site.

    3 Como contribuir

    O processo é o mesmo de qualquer projeto aberto no GitHub: 

    Fork  →  Edit  →  Commit  →  Pull Request

    Fork cria uma cópia do repositório na sua conta. Edit é você alterar os arquivos (pelo navegador mesmo, sem instalar nada). Commit salva as mudanças. Pull Request pede pra equipe de Laços Profanos juntar suas mudanças no repositório oficial.

    Nunca usou GitHub? A documentação oficial em português explica tudo: docs.github.com/pt .

    O que você edita no fork

    Cada categoria de artigo segue o mesmo padrão. Usando um personagem como exemplo:

    1. Vai na pasta personagens/ do seu fork e clica em Add file → Create new file
    2. Escreve nome-do-artigo/index.html (o GitHub cria a pasta automaticamente)
    3. Copia o conteúdo de um artigo que já existe (o Wahi é o exemplo mais completo) e troca o slug no index.html
    4. Repete pros outros arquivos do artigo (<slug>.json, conteudo.md, galeria.json), sempre copiando de um artigo que já existe
    5. Edita o <categoria>.json (ex: personagens/personagens.json) e adiciona o slug na lista
    6. Commit + Pull Request
    Ficou perdido? Olha o Wahi — é o exemplo mais completo, e todos os artigos seguem o mesmo padrão.

    O que acontece depois

    • Seu PR chega no repositório oficial
    • A equipe de Laços Profanos revisa — pode levar alguns dias
    • Se precisar de ajuste, a equipe comenta direto no PR
    • Você corrige, faz novo commit, e o PR atualiza sozinho
    • Quando aprovado, é mesclado e o site é republicado em 1-2 min

    4 Regras

    O que é permitido

    • Informações oficiais sobre personagens, bestiário, símbolos, organizações e universo
    • Curiosidades confirmadas (comentário da autora, entrevista, post oficial)
    • Teorias e headcanons — desde que marcados como não-oficiais
    • Correção de erros, ortografia, links quebrados e dados desatualizados
    • Melhorias no código: CSS, bugs, acessibilidade, funcionalidades novas

    O que é proibido

    • Conteúdo sexual de qualquer tipo.
    • Off-topic — só vale conteúdo sobre Laços Profanos.
    • Spoiler recente — espere 1 mês após o lançamento.
    • Teoria escrita como fato — sempre marca como não-oficial (ver bloco abaixo).
    • Opinião pessoal — o artigo descreve, não julga.
    • Falta de respeito — xingamento, ataque, briga em comentário de PR.
    • IA sem revisão — pode usar pra ajudar, mas revisa antes de mandar.
    • Vandalismo — ban imediato.
    • Subir imagem pro repositório — usa URL externa (Imgur, Drive público, etc).
    • Arte de fã sem permissão — se o autor não autorizou, não coloca.

    Melhorias no site

    Pode mexer no código: melhorar CSS, corrigir bugs, ajustar acessibilidade. Se você programa e quer adicionar alguma funcionalidade nova, é muito bem-vindo.

    Antes de mexer em algo grande, abre uma Issue no repositório descrevendo o que você pretende fazer. A gente conversa sobre a abordagem antes de você mandar o código.

    Regras pra mudanças no código:

    • Mexer mais do que o necessário — sem reformatar arquivo inteiro, sem trocar nome de classe sem motivo, sem "limpar" código que funciona.
    • Mudança grande sem discussão prévia — abre uma Issue primeiro explicando.
    • Quebrar compatibilidade — não remove funcionalidade existente sem motivo.

    Como marcar uma teoria

    Teoria é bem-vinda, só precisa ficar claro que não é oficial. Usa citação no Markdown: 

    > 💭 **Teoria (não oficial):** aqui vai sua teoria,
> com argumentos e referências.

Depois continua o texto normal.

    Fica assim no site:

    💭 Teoria (não oficial): baseado na cena do capítulo 3, é possível que Wahi tenha origem em uma linhagem antiga de metamorfos. A obra ainda não confirmou isso.

    Spoilers recentes

    Se for realmente necessário falar de algo com menos de 1 mês, coloca aviso gigante no topo: 

    ## ⚠️ ATENÇÃO: CONTÉM SPOILERS DE CONTEÚDO RECENTE

Este artigo contém informações reveladas em [capítulo X],
lançado em [data]. Leia por sua conta e risco.
    Sem aviso = PR recusado pela equipe.

    5 Dicas

    Não são obrigatórias, mas ajudam sua contribuição a ser aceita mais rápido:

    • PRs pequenos — fica mais fácil pra equipe revisar.
    • Escreve a mensagem do commit antes de mexer — ajuda a manter o foco.
    • Revisa ortografia — passa um corretor antes de mandar.
    • Mantém consistência — olha como outros artigos estão formatados e segue o padrão.
    • Não deixa PR aberto por meses — se não vai continuar, fecha e abre outro depois.
    • Dúvida? Olha o Wahi — é o exemplo mais completo.
